### Lockout Risk Assessment

**HIGH** — Enabling an IP allowlist would:
1. Block all Base44 workflow triggers (Schedule Checker, Nightly Test Run, Retention Reaper, Governance Heartbeat) — their source IPs are provider-managed and not independently verifiable
2. Block all MCP client connections (ChatGPT, Claude) — dynamic IPs
3. Block all automation clients — dynamic IPs
4. Block operator browser access if IP changes (residential dynamic)
5. Provide no security benefit against the primary threat model (API key compromise, not IP spoofing)

### Classification

**NOT RECOMMENDED FOR CURRENT ACCESS MODEL**

No proposed allowlist entries — none are independently verifiable. The existing API key authentication + rate limiting + RLS provides adequate security without IP restrictions.

### Optimized Daily Checklist

**DAILY (lightweight, ~5 min):**
1. Dashboard loads, engine status = healthy
2. Check pool health (active_sessions < max, pool warm)
3. Check Errors page for new Critical/High patterns
4. Check rate-limit health (no sustained 429s)
5. Review AuditLog for unexpected admin actions (heartbeat + create/run only is normal)
6. Check orphan detection (recoverOrphans ran, no stale sessions)
7. Lightweight browser smoke test: create session → goto → screenshot → terminate
8. Lightweight job smoke test: run a 2-step job (goto + extract_text) → verify result

**WEEKLY (~15 min):**
1. Deployment drift check (getDeploymentStatus → 0 functional drift)
2. Audit log full review
3. Credential rotation check (secrets current, rotate if >90 days)
4. Backup verification (JobVersion checkpoints for critical jobs)
5. Error pattern deep review (recurring patterns, root cause analysis)

### Certification Suite Cadence Recommendation

| Suite | Current | Recommended | Rationale |
|-------|---------|-------------|-----------|
| 23/23 Runtime Suite | Nightly (workflow) | **AFTER CHANGE ONLY** | Expensive (creates sessions, runs jobs, tests security); daily runs consume engine resources without adding safety when no code changed |
| 47/47 Master Release | Not scheduled | **INCIDENT RESPONSE ONLY** | Very expensive (runs all black-box suites); only needed when investigating incidents or validating a release candidate |

**Rationale:** Running 23/23 nightly provides no safety benefit when no code has changed — it only consumes engine sessions, API credits, and database records. The automated workflows (Schedule Checker, Retention Reaper, Governance Heartbeat) provide continuous lightweight monitoring. Certification suites should run after code changes (post-deploy verification) or during incident response.
